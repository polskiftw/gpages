No Cheat Tags

Nuclear Valheim cheat-marker suppression: item flags are scrubbed, cheated arguments and ItemCheated checks are forced clean, the native bypass is forced in memory, character cheat-history markers are suppressed, and world-object cheat flags read/write as false.

Download NoCheatTags.dll

Hosted build: 2026-09-28 15:04:09 UTC

BepInEx 5 + Harmony. Version 1.3.2. Audited against the refreshed Valheim 1.0.16 decompile and raw Managed assemblies.

What it forces

ItemData.m_cheated: every current vanilla direct write identified in the Valheim 1.0.16 decompile is forced to store false, including current-format item deserialization, Inventory.AddItem paths, ItemDrop.OnCreateNew, CharacterDrop drops, piece/container returns, and old-world conversion. Inventory.Load also performs one final cleanup pass after deserialization, and ItemData.Save cleans before serialization.
cheated arguments: every boolean parameter literally named cheated in the Valheim gameplay assembly is forced to false.
ItemCheated(...): every bool-returning method with that name returns false.
PlayerProfile.s_bypassCheatChecks: returns true in memory without invoking the vanilla command or writing its saved bypasscheatchecks key.
PlayerProfile.m_usedCheats: existing values are cleared on profile load/save paths, the vanilla console write is removed from Terminal.ConsoleCommand.RunAction, and the active profile is scrubbed around command execution as a fallback.
PlayerStatType.Cheats: PlayerProfile.IncrementStat ignores this one stat and existing values are reset to zero across the profile's player-stat tracks.
ZDO cheat markers: s_cheated and the eight queued cheat slots cannot be written true and are read as false.

Linux resolver fix in 1.3.2

The raw 1.0.16 Managed files contain both assembly_valheim.dll and a small Assembly-CSharp.dll. The gameplay classes ItemDrop and ItemDrop+ItemData are in assembly_valheim.dll; Assembly-CSharp.dll contains neither. Earlier builds used one OR-based first-match lookup, so Linux/Mono could select Assembly-CSharp first and then fail every gameplay-type lookup. Version 1.3.2 explicitly prefers assembly_valheim, only falling back to Assembly-CSharp if the gameplay assembly is absent.

Existing inventory cleanup

Version 1.3.0 removes the 1.2 polling approach entirely. The current player-load path calls Inventory.Load, which deserializes each item through ItemDrop.ItemData.Load. The plugin forces that exact m_cheated store to false, then performs a one-time post-load pass over the real Inventory.m_inventory list as a defensive check. There is no 500 ms scan and no continuous inventory polling.

Persistence

Loaded item flags are actually cleared in memory and are clean when those items are next saved. World ItemDrop data uses the same ItemData.Load/ItemData.Save serialization path, so loaded world items receive the same treatment. Existing raw world-ZDO cheat bits are neutralized on read and new true writes are blocked; the mod does not bulk-rewrite untouched dormant ZDO records just for cosmetic cleanup.

The vanilla dev bypass

The vanilla command persists a character key named bypasscheatchecks. This plugin does not use that command or setter; it patches the getter result in memory instead, so installing the plugin does not create that saved key. Existing keys are left alone.

Install
  1. Install BepInEx 5 for Valheim.
  2. Download NoCheatTags.dll.
  3. Put it in Valheim/BepInEx/plugins/.
  4. Restart Valheim.

For absolute world-side suppression on a dedicated/listen server, install it on the authoritative host/server too.
