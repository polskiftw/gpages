What changed in v7

v7 starts with a completely separate local database and does not import any v3-v6 tags. It uses the measured hard cap of 40, supports tags beginning with letters or digits, learns the site's same-origin JSON autocomplete request locally, then calls that endpoint directly instead of typing every query into the page. The crawl is strict breadth-first: 36 one-character roots first, then only descendants of saturated prefixes. Any query returning fewer than 40 closes that substring globally, so every future prefix containing it is skipped. Popularity counts never influence crawl decisions. If v7 already knows that a candidate is itself a real tag and already knows at least 40 tags containing that candidate, it can mark that candidate saturated without spending another server request.

Why this cuts queries safely

A result below 40 proves every tag containing that substring has already been returned. Because a closed substring covers the whole database, not just one prefix branch, v7 reuses it everywhere. Breadth-first order makes the shortest proofs available before longer queries are generated. A 40-row response remains unresolved because the endpoint exposes no total, cursor, larger limit, or pagination. v7 therefore expands only where completeness still requires it.
